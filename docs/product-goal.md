# プロダクトの目的(North Star) — アグレッシブ運用モード

> **運用モード: アグレッシブ（積極改善）。** 保守版のスナップショットは
> `docs/archive/2026-07-25-conservative/` に保存。元に戻したくなったらそちらを復元する。
> このモードは PoC の実験（「シグナルが無くても、自律ループが積極的に改善・拡充を続けられるか」の検証）。
> オーナーは長期不在で監視できない前提。だからこそ**壊さない床**（後述）は絶対に守る。

## North Star(目的) — 体験の質のバスケット

**「子どもが、なぞって"正しく"星座を見つけられ、集めて楽しい」体験の質を高め続ける。**

3軸のバスケット（優先度は上から）:
1. **判定の正確さ** — なぞりが正しく解決される質。
2. **コンテンツの広がり** — 集められる星座の種類・世界観の豊かさ。
3. **楽しさ・体験** — 見た目・手触り・オンボーディング・磨き込み。

## ★ アグレッシブ運用の大原則（保守版からの最大の変更点）

- **シグナル待ちをしない。** 外部フィードバックやメトリクスが乏しくても、**下記ロードマップと自分の点検（dogfooding）に基づいて、自発的に改善・コンテンツ拡充を提案し実装し続ける**。「データが乏しいから提案なし」で休止しない。
- **手を止めない。** 利用者が少なくても、プロダクトを良くする仕事は常にある（コンテンツ・磨き込み・品質・性能）。
- **自己検証で品質を担保する。** 利用者が少なくKPIはノイズだらけなので、KPIの上下に一喜一憂しない。代わりに**テスト・型・ビルド・（可能なら）自分でアプリを触っての点検**で良し悪しを判断する。
- **前進を優先しつつ、加算的・可逆的に。** 迷ったら「小さく・足す・戻せる」変更を選ぶ。機能削除や破壊的変更、大規模リファクタは避ける。

## ロードマップ（自発的な提案・実装の源。上から順に消化してよい）

1. **黄道十二星座の完備** — 残り: **かに座・てんびん座・いて座・やぎ座・うお座**（実座標ベースで1つずつ追加）。
2. **"おはなし星座"の拡充** — モナリザ座・ラーメン座・ネコ座の路線で、子どもが喜ぶ楽しい星座を増やす。
3. **なぞり体験の磨き込み** — 判定精度、ヒント、初回オンボーディング、「みつからないね」時の再挑戦導線。
4. **演出・季節性** — 星空・月・オーロラ等の磨き込み、季節の星座やイベント。
5. **自己検証できる品質改善** — アクセシビリティ、性能(60fps維持)、テスト網羅、コードの整理（挙動を変えないリファクタ）。

「今日やる価値のあること」が思いつかない日でも、上のどこかから必ず一手を選べる。ただし**同じ所を何度もいじり直す（thrash）ことはしない**。既に下した判断・実装は尊重する。

## ⭐ 守るガードレール（数値やスピードより優先）

- **中核体験を壊さない。** 「なぞって正しく見つかる」を損なう変更は不可。判定（`shapeMatcher`）に関わる変更は、テスト内シミュレーションで裏取りし、**体感の悪い誤マッチ（全然ちがう星座への確信度の高い誤判定）を増やさない**こと。
- **子ども向けの健全さ。** ダークパターン（依存を煽る仕掛け・射幸性・通知連打）は禁止。
- **プライバシー方針は不変**（匿名・個人情報を集めない）。

## 🧯 壊さない床（アグレッシブでも絶対に外さない・監視不在ゆえ必須）

- **CI が緑でなければマージしない**（本番を壊さないための最後の砦）。
- **`infra/**`（CloudFormation等）と `.github/**`（ワークフロー）は自動で変更・マージしない** → 人間レビューへ回す（オーナー帰還まで保留でよい）。AWS・課金・セキュリティ・CI自体の事故を防ぐ。
- **1 Issue = 1 PR**（＝1コマンドで revert できる粒度を保つ）。
- **`hold` ラベルと Routine 一時停止**は常に有効な緊急停止。
- 依存の大量追加や、正当な理由のない大規模変更はしない。

## 運用ルール（Builder / Reviewer への指示）

- **Builder（提案・実装）**: 上記ロードマップ／自分の点検から価値ある改善を選び、**承認を待たずに実装してPRを出してよい**。1回の実行で**最大3件**（各 S/M・1 Issue=1 PR）。ユーザーに見える変更は `releaseNotes.ts` の先頭に追記。判定系はテストで裏取り。
- **Reviewer（承認・マージ）**: PRを**積極的にマージ**する（1日最大3件）。ただし**壊さない床**を厳守（CI緑・infra/.github は人間へ・差分過大は分割要請・中核体験やテストを壊すものは不可）。`hold` が付いたものには触らない。
